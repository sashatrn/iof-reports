## Project

`iof-reports` is a TypeScript CLI for generating Ukrainian orienteering reports from IOF XML 3.0 exports, mostly from MeOS. It produces PDF, HTML preview/render files, and limited DOCX output.

Main user-facing reports:

- `individual` and `team`
- `side-by-side-relay`
- `side-by-side-rogaining`
- `side-by-side-summary`
- `rogaining`
- `rogaining-awards`
- `rogaining-diplomas`
- `rogaining-score`
- `rogaining-results`
- `rogaining-results-score`
- `rogaining-splits`
- `military-individual`
- `military-relay`
- `military-team`

The README is in Ukrainian and is the source of truth for CLI examples and user-facing behavior.

## Commands

- Install dependencies: `npm install`
- Run tests: `npm test`
- Build: `npm run build`
- Dev CLI: `npm run dev -- <xml> [args]`
- Sample run: `npm run dev:sample`
- Rogaining sample: `npm run dev:rogaining`
- Watch mode: `npm run dev:watch -- --input-dir ./incoming --output-dir ./out --report rogaining --port 4173`

The package requires Node.js 18+. PDF rendering uses Playwright Chromium, so environments may need `npx playwright install chromium`.

## Entry Points

- [src/index.ts](/Users/atrukhny/projects/my/iof-reports/src/index.ts): top-level CLI entry. Dispatches `watch`, loads config, parses CLI args, reads XML inputs, calls report generation, writes HTML/PDF/DOCX outputs.
- [src/cli.ts](/Users/atrukhny/projects/my/iof-reports/src/cli.ts): normal CLI argument parsing and validation.
- [src/report-types.ts](/Users/atrukhny/projects/my/iof-reports/src/report-types.ts): canonical report type list and type guards.
- [src/core/generate-report-html.ts](/Users/atrukhny/projects/my/iof-reports/src/core/generate-report-html.ts): central dispatcher from XML plus options to generated report artifacts.

Important behavior in `generateReportsHtml`: `--report all` generates one combined regular side-by-side `individual` report whose PDF includes both individual results and team standings. Explicit `--report team` still generates the standalone team report.

## Config

Configuration is loaded by [src/config.ts](/Users/atrukhny/projects/my/iof-reports/src/config.ts). Defaults are embedded in code and can be overridden with `--config` / `-c`. The repository has:

- [config.json](/Users/atrukhny/projects/my/iof-reports/config.json): default example config.
- [config-masters.json](/Users/atrukhny/projects/my/iof-reports/config-masters.json): alternate rogaining score config.

Notable config areas:

- `ignoredStatuses` controls result statuses skipped by parsers.
- `leftLogo` and `rightLogo` optionally override PDF header logos; relative paths are resolved from the config file directory.
- `genderMapping` maps class prefixes.
- `side-by-side.teamRules` controls regular team report composition.
- `military` controls military point filters and grouping.
- `rogaining.controlGateRule`, `rogaining.scorePoints`, `rogaining.scoreReport`, and `rogaining.resultsReport` control rogaining-specific reports.

## Parsing Notes

- [src/io/parse-iof.ts](/Users/atrukhny/projects/my/iof-reports/src/io/parse-iof.ts) parses individual `ClassResult` / `PersonResult` data into `Participant`.
- [src/io/parse-rogaining-iof.ts](/Users/atrukhny/projects/my/iof-reports/src/io/parse-rogaining-iof.ts) parses `TeamResult`-style rogaining/team data into `RogainingTeam`.
- [src/io/parse-course-data.ts](/Users/atrukhny/projects/my/iof-reports/src/io/parse-course-data.ts) supports `rogaining-splits` via `--courses`.
- [src/io/parse-uof-baza.ts](/Users/atrukhny/projects/my/iof-reports/src/io/parse-uof-baza.ts) supports official rogaining results via `--baza`.

CLI validations require:

- `rogaining-splits`: `--courses <courses.xml>`
- `rogaining-results`: `--baza <baza.xml>`
- `military-team`: `--relay <relay.xml>`
- `side-by-side-summary`: optional companion XML files via `--rogaining`, `--relay`, or explicit repeated `--series type=file.xml`

`rogaining-results-score` also requires `bazaXml` in generation code, but normal CLI validation currently only enforces `--baza` for `rogaining-results`; verify this before changing related behavior.

## Watch Mode

Watch mode is started with `iof-reports watch ...`.

Watch accepts `--report side-by-side-individual` for the regular individual Пліч-о-пліч generator. This report supports an IOF XML with classes but no participants yet, matching the empty-input behavior of `military-individual`. The old `--report individual` name is not a watch-mode option. Watch also accepts `side-by-side-relay`, `side-by-side-rogaining`, and `side-by-side-summary`. For summary watch mode, latest XML is the primary individual source and optional static companion files can be passed with `--rogaining` and `--relay`.

Key files:

- [src/watch/cli.ts](/Users/atrukhny/projects/my/iof-reports/src/watch/cli.ts): watch args.
- [src/watch/run-watch-mode.ts](/Users/atrukhny/projects/my/iof-reports/src/watch/run-watch-mode.ts): poll loop, latest XML selection, stability check, report regeneration.
- [src/watch/http-server.ts](/Users/atrukhny/projects/my/iof-reports/src/watch/http-server.ts): local server routes.
- [src/watch/viewer-page.ts](/Users/atrukhny/projects/my/iof-reports/src/watch/viewer-page.ts): viewer shell.

Watch output directory contains:

- `report.html`
- `report.pdf.html`
- `viewer.html`
- `meta.json`
- `.watch-state.json`

Viewer URLs:

- `/viewer`
- `/report`
- `/report-pdf`
- `/meta`

Watch hashing currently includes main XML, optional course data XML, and optional summary companion XML files.

## Development Conventions

- Keep changes scoped to source, templates, config, docs, or tests relevant to the requested behavior.
- Prefer existing report builder and template patterns over new abstractions.
- When adding a report type, update `REPORT_TYPES`, CLI usage/validation, `generateReportHtml`, README, tests, and any watch-mode restrictions if applicable.
- Keep regular Пліч-о-пліч individual/team/relay internals under the `side-by-side-*` module/template prefix while preserving existing CLI report values unless the external interface is intentionally changed.
- For user-visible Ukrainian text, match existing Ukrainian wording and typography.
- Use structured XML parsing via `fast-xml-parser`; avoid ad hoc string parsing.
- Before editing generated/compiled files under `dist`, check whether the project expects source-only changes plus `npm run build`.
- Preserve user changes in the working tree. Do not revert unrelated files.
